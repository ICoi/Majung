# Majung 상견례 초대장

## 목적과 범위

- 약 10명의 가족에게 링크와 공통 비밀번호로 전달하는 일회성 초대장이다. 초기 구현 예산은 3시간 이내이며, 완료 이후 지속 운영·기능 확장을 전제로 하지 않는다.
- HTML·CSS·JavaScript 기반 한 페이지를 GitHub Pages에 게시한다. 별도 서버, 가입, 데이터베이스는 두지 않는다.
- 참석 응답, 방문 통계, 일정 저장, 자동 종료는 현재 범위에 포함하지 않는다. 사용자가 변경을 요청하면 새 요구사항을 반영한다.

## 합의된 화면

- 비밀번호를 입력한 뒤 두 사람의 사진으로 시작한다. 메뉴나 탭 없이 스크롤로 전체 내용을 읽는다.
- 초대장을 연 뒤 스크롤 전에는 화면 하단에 블러 배경의 스크롤 안내를 띄운다. 실제로 한 번 스크롤하면 사라지고 같은 페이지에서 맨 위로 돌아와도 다시 나타나지 않는다. 안내가 터치·스크롤을 가로막거나 화면을 자동으로 이동시키지 않도록 한다.
- 잠금 화면에는 비밀번호가 두 사람의 결혼식 날짜임을 안내하고 년·월·일 각 두 자리의 6자리 형식(YYMMDD)을 설명한다. 입력란에는 결혼식 날짜와 예시 `000000`을 표시하고 숫자 키패드를 요청한다. 실제 날짜·비밀번호는 평문으로 표시하지 않는다. 비밀번호 보기 버튼과 잠금 화면의 예시 초대장 안내 문구는 표시하지 않는다.
- 사진·초대 문구 → 날짜·요일·시간 → 장소·주소·예약명 또는 룸 → 양가 참석자 관계·이름 → 약도·찾아오는 길 → 네비게이션·주차 안내 순서로 구성한다.
- 초대 문구는 결혼식 초대장처럼 거창하거나 딱딱하지 않게, 양가 가족이 인사를 나누는 식사 자리라는 의미를 담는다. 짧은 두 문단으로 행 길이에 차이를 주며 사용자가 확정한 문구는 요청 없이 다시 다듬지 않는다. 실제 문구는 `.private/content.json`, 개인정보 없는 예시는 `content.example.json`의 `invitation`에 보관한다.
- 대문·마무리의 이름은 로컬 `displayNames`를 사용해 성을 뺀 친근한 이름으로 표시한다. `couple`의 실명과 가족 소개 제목은 유지한다. 예약 안내는 예약자 이름으로 예약했다는 짧은 문장으로 적는다.
- 가족 소개는 양가별 가족사진 한 장씩과 그 아래 관계·이름으로 구성한다. 가족별 영역은 넓은 화면에서도 세로로 배치하고 사진 전체 비율을 유지한다. 개인별 사진이나 소개 문구는 별도 요청 없이 추가하지 않는다. 실제 가족사진이 없으면 예시에서는 자리 표시자를 사용한다.
- 따뜻한 크림·베이지 바탕과 짙은 브라운 글씨, 충분한 여백을 사용한다. 기본 바탕은 크림 `#fffaf2`, 본문은 다크 브라운 `#3f2c24`, 강조는 브라운 `#81583f`로 맞춘다. 잠금 화면·본문·버튼·사진 자리·예시 약도까지 색감을 통일하고 보조 글씨도 읽기 충분한 대비를 유지한다. 배경 애니메이션·스크롤 연출은 추가하지 않는다.
- 오시는 길은 차량 안내만 제공한다. 대중교통·역·출구·도보 안내는 화면과 필수 입력 항목에서 제외한다. 네비게이션 검색어·차량 도착 주소·약도는 식당 앞 도착 동선과 일치시킨다.
- 사용자가 알려준 대로 식당 앞과 옆에 넉넉한 주차 공간이 있으며, 당일 공간이 부족하면 발렛 서비스를 편하게 이용할 수 있다고 안내한다. 발렛 요금·운영 시간·차량 인계 위치 등 추가 정보는 확인된 경우에만 표시한다. 미확정 사실을 추측해서 채우지 않는다.
- 오시는 길은 ① 앱으로 길 안내 받기 ② 약도·주소 확인 ③ 주차 안내 순서로 구성한다. 앱 버튼을 큰 브라운 버튼으로 가장 강조하고, 직접 검색하는 방법은 접어 둔다. 중복된 차량 안내·검색어·주소를 같은 비중으로 나열하지 않는다. 위치 설명은 짧게, 주차 핵심 문구는 별도 상자와 굵은 글씨로 구분한다.
- 네이버지도·카카오맵 링크, 식당 주소·네비게이션 검색어 복사를 제공한다. 복사 성공 및 실패 시 직접 복사할 수 있는 안내를 표시한다.
- 카카오맵·T맵·네이버지도 버튼으로 휴대폰의 외부 앱을 열고 같은 목적지를 전달한다. 카카오맵은 자동차 길찾기, T맵·네이버지도는 내비게이션 목적지 연결을 사용한다. 지도를 내장하거나 사용자의 현재 위치를 초대장에서 수집하지 않는다. 세 앱 모두 앱 링크로 연결하며 API 키나 별도 공유 링크를 요구하지 않는다. 카카오맵을 카카오내비로 표시하지 않는다.
- 목적지 이름·주소·좌표는 `.private/venue.json`에 보관한다. 이 파일은 예시와 실제 빌드 모두에 덮어 적용한다. 앱이 열리지 않을 때는 주소 복사·웹 지도로 이어갈 수 있게 한다. 앱 실행 성공 여부는 실제 iOS·Android 기기 확인 전까지 보장하지 않는다.
- 내비게이션 버튼 위에는 버튼을 누르면 앱으로 이동한다는 설명과, 상견례 당일 평소 쓰는 앱의 버튼으로 식당까지 길 안내를 받을 수 있다는 안내를 읽기 쉽게 표시한다. 부모님이 버튼 이름만 보고 용도를 추측하게 하지 않는다.

## 큰 글씨를 기본으로 고려

- 양가 부모님이 휴대폰 글씨를 크게 설정할 수 있다는 전제로 모바일 단일 열을 우선한다. 넓은 화면에서는 본문 최대 너비를 제한한다.
- 글씨는 `rem` 기준으로 작성하고 글자·화면 확대를 허용한다. 텍스트 상자에는 고정 높이, 줄 수 제한, 말줄임을 사용하지 않는다.
- 긴 이름·주소·버튼 문구는 줄바꿈하고, 공간이 부족하면 정보와 버튼을 세로 배치한다. 작은 글씨로 줄여 맞추지 않는다.
- 사진은 원래 비율을 유지하고 얼굴이 잘리지 않게 배치한다. 버튼에는 충분한 터치 영역을 확보한다.
- 첫 화면의 두 사람 사진을 사용자가 제공하면 원본을 `.private/`에 보관하고 미리보기부터 반영한다. 사진이 없을 때만 자리 표시자를 사용한다. 사진은 5MB, 약도는 3MB까지 내장할 수 있으며 임의로 얼굴이나 구도를 보정하지 않는다.
- 약도는 이미지로 제공하되 같은 내용을 텍스트로도 설명한다. 이미지 안의 글씨만으로 필수 안내를 전달하지 않는다.
- 사용자가 제공한 실제 약도를 `.private/`에 보관해 미리보기와 실제 빌드에 함께 반영한다. 이미지 비율을 유지하고 약도 이미지 클릭과 크게 보기 버튼 모두 같은 확대 화면을 연다. 닫기 기능을 제공하며 확대 이미지는 본문의 이미지 데이터를 재사용하고 원본을 공개 파일로 따로 올리지 않는다.

## 개인정보와 암호화

- StatiCrypt로 초대장 본문과 대문 사진·양가 가족사진·약도를 함께 암호화한다. 이미지는 본문 안에 내장하며 실제 사진의 외부 URL은 사용하지 않는다.
- 실제 내용·사진·약도·비밀번호는 Git에서 제외된 `.private/`에만 보관한다. 원본을 만들기 전 추적 제외 상태를 확인한다.
- 사용자가 확정한 실명·일시·예약·가족 정보는 `.private/content.json`에 반영하고 예시 미리보기에서도 이 파일을 우선 사용한다. 가족 목록은 사용자가 준 관계·이름만 표시하며 본인이나 다른 참석자를 임의로 추가하지 않는다. 사진·실제 약도가 아직 없으면 미리보기에는 자리 표시자를 유지하고 실제 배포 완료로 표현하지 않는다.
- 공개 저장소에는 암호화 결과물과 개인정보가 없는 제작 도구·예시·지침만 올린다. GitHub Pages에는 `dist/`만 배포한다.
- 공개 제목·미리보기에는 일반적인 ‘상견례 초대장’ 문구만 사용한다. 이름·일시·위치·사진·비밀번호를 공개 메타데이터, 로그, 커밋 메시지, 스킬에 넣지 않는다.
- 비밀번호는 URL·코드에 넣거나 브라우저에 자동 저장하지 않는다. 실제 배포용 비밀번호는 사용자가 정한 숫자 6자리를 사용하며 앞자리 0도 보존한다. 길이·복잡도 조건을 임의로 강화하지 않는다. 로컬 예시는 비어 있지 않은 사용자 지정 비밀번호를 허용하고 재생성 시에도 로컬 비밀번호 파일의 값을 유지한다. 비밀번호 값 자체는 스킬에 기록하지 않는다. 링크와 비밀번호를 가진 사람은 누구나 열 수 있는 공통 비밀번호 방식이다.

## 검색 제외

- 구글·네이버 검색 결과에 초대장이 노출되지 않도록 잠금 화면과 복호화된 본문 모두 최초 HTML `head`에 `robots` 메타 태그의 `noindex`를 유지한다. `nofollow`, `nosnippet`, `noimageindex`도 유지한다.
- JavaScript 실행이나 비밀번호 입력 이후에만 검색 제외 설정을 추가하지 않는다. 빌드 시 두 화면을 검사하고 공개 파일·배포 검사에서도 누락을 차단한다.
- `noindex`를 읽지 못하게 하는 `robots.txt`의 수집 차단을 함께 적용하지 않는다. 사이트맵 생성·검색엔진 등록도 진행하지 않는다.
- 검색 제외는 접근 통제가 아니므로 암호화를 유지한다. 검색엔진의 지침 준수와 반영 시점까지 보장한다고 표현하지 않는다. 공개 GitHub 저장소 자체의 검색 여부는 초대장 페이지 설정과 별개다.

## 방향 변경 시 함께 갱신

- 이 파일을 프로젝트의 합의된 방향과 작업 방식의 기준으로 유지한다. 사용자의 최신 명시적 요청을 기존 지침보다 우선한다.
- 사용자가 목적·범위·화면·디자인·접근 방식·배포 방식·검증 기준·커밋 정책을 바꾸면 구현과 함께 이 파일의 해당 항목을 수정한다. 관련 사용법이 달라지면 README도 수정한다.
- 새 결정을 해당 항목에 통합하고 대체된 내용을 지운다. 서로 충돌하는 지침이나 대화·변경 이력을 계속 덧붙이지 않는다.
- 탐색 중인 선택지나 아직 채택되지 않은 제안은 확정 사항으로 기록하지 않는다. 기존 코드가 요구사항과 다르면 스킬을 코드에 맞춰 낮추지 말고 차이를 해결하거나 미완료로 보고한다.
- 새로운 사용자 요구가 없는 한 구현 세부 변경마다 스킬을 수정할 필요는 없다. 실제 행사 정보는 스킬이 아닌 `.private/`에서만 갱신한다.

## 검증과 작업 단위별 커밋

- 시작할 때 Git 상태를 확인하고 기존 사용자 변경과 이번 작업을 구분한다.
- 하나의 설명 가능한 변경이 완성되면 관련 검증 후 로컬 커밋을 만든다. 예: 화면 구성, 암호화 빌드, 길 안내 기능, 프로젝트 지침. 의미 없는 파일별 분할이나 미완성·검증 실패 상태의 커밋은 피한다.
- 기능·빌드 변경은 `npm test`와 관련 빌드·브라우저 확인을 수행한다. 문서·스킬만 바꾸면 링크·내용·스킬 형식을 확인하며 불필요하게 암호화 결과물을 재생성하지 않는다.
- 반응형 변경은 320px·390px·768px 너비와 200% 글씨에서 가로 넘침·겹침·잘림을 확인한다. 실제 모바일 Safari·Chrome 검증을 하지 못했다면 그 한계를 보고한다.
- 올바른/틀린 비밀번호, 사진·약도 복원, 지도 목적지, 복사 동작을 관련 변경에 맞게 확인한다. 검증되지 않은 결과를 통과로 표현하지 않는다.
- 필요한 파일만 명시적으로 스테이징하고, 커밋 전 staged diff와 파일 목록을 확인한다. `.private/`, 원본 이미지·내용, 비밀번호, 무관한 사용자 변경을 포함하지 않는다.
- 커밋 메시지는 변경 목적을 설명하고, 방향 변경에 따른 스킬·문서 갱신은 관련 구현과 같은 커밋에 담는다. 마지막 보고에는 커밋과 검증 결과, 남은 작업을 간단히 적는다.
- 로컬 커밋 권한을 원격 푸시·배포 권한으로 확대 해석하지 않는다. 실제 자료가 없으면 예시로 확인하고, 예시를 실제 초대장으로 배포하지 않는다.

## 실행과 완료 기준

- 세부 설치·내용 입력·빌드·배포 절차는 저장소 루트 [README](../../../README.md)를 참고하고 실제 `package.json`과 스크립트를 확인한다.
- 예시 생성: `npm run demo`. 미리보기: `npm run preview`. 200% 글씨 검사 화면: `npm run demo:large-text`.
- 실제 자료 반영 후 `npm run build`, `npm test`, `node scripts/check-public.mjs --production`으로 확인한다. 암호화·검증은 로컬에서 끝내며 GitHub에 원본이나 비밀번호를 등록하지 않는다.
- 실제 사진·일시·장소·가족·교통·주차 정보가 반영되고, 공개 파일·Git 기록에 원본이 없으며, 배포된 링크가 검증되어야 서비스 완료다. 예시 구현·배포 준비·실제 배포를 구분해 보고한다.
